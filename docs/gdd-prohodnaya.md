## 1. Vision

**Elevator pitch.** Ты — дежурный на проходной: перед тобой очередь существ с пропусками, на доске — правила дня. Сверь признаки гостя с документом и правилами: своих — пропусти, самозванцев — разверни. Одна смена = одна сессия 3–5 минут.

**Player fantasy.** «Я внимательный, меня нельзя обмануть» — мгновенная читаемость обмана и удовлетворение от верного штампа (MDA: Challenge + Sensation).

**Три столпа:**

1. **«Сверка за 10 секунд».** Любая заявка читается и решается за 10–20 секунд: пиктограммы, максимум 3 активных правила, ноль длинных текстов.
2. **«Правила растут вместе с тобой».** Каждые 1–2 смены вводится один новый тип правил, старые не исчезают, а уходят в ротацию — сложность растёт пилой, без обрывов.
3. **«Ошибка учит».** Любая ошибка мгновенно объясняется конкретным несовпавшим признаком. Игра никогда не наказывает молча (SDT: Competence).

**Anti-vision — чем игра НЕ является:**

- Не Papers, Please: никакой истории и чтения абзацев — только визуальная сверка примитивов.
- Не хоррор и не жуть: мемная доброжелательность, никаких скримеров и «страшных» аномалий.
- Не симулятор бюрократии: максимум 3 активных правила, максимум 2 признака в одном правиле, никаких «если А и не Б, но при В».
- Не плати за прогресс: ни одна rewarded-награда не даёт постоянного преимущества, всё достижимо без рекламы.
- Не таймкиллер со случайностью: у каждой заявки ровно один детерминированный верный ответ, никакого «повезло».

## 2. Кор-геймплей: полный разбор одной заявки

**Экран (портрет, поддержка обеих ориентаций через Phaser Scale.FIT):**
- Верх: **доска инструкций** — до 3 слотов, каждый слот = пиктограмма 32×32 px + формулировка ≤ 8 слов, шрифт ≥ 16 px.
- Центр: **гость** (процедурный персонаж) и **пропуск** — карточка ~240×340 px с полями: пиктограмма головы (форма+цвет), пиктограмма тела (форма+цвет), глаза, аксессуар, срок действия «ГОДЕН ДО: день N», подпись (галочка/росчерк), имя (декоративное, слоги).
- Низ: две кнопки ≥ 72×72 px, отступ между ними ≥ 16 px: **«ПРОПУСТИТЬ»** (зелёная) и **«РАЗВЕРНУТЬ»** (красная).

**Единая семантика решения (единственное правило игры):**

> **ПРОПУСТИТЬ**, если документ полностью совпадает с гостем И гость не нарушает ни одного активного правила дня. Иначе — **РАЗВЕРНУТЬ**.

Отсюда три типа невалидных гостей, каждый ровно с **одной** причиной отказа: (а) **подделка** — документ ≠ гость по одному полю; (б) **нарушитель** — документ верен, но гость нарушает ровно одно активное правило; (в) смешанных нет (инвариант генератора, раздел 3).

**Тайминг одной заявки:**

| t | событие |
|---|---|
| 0.0 с | Гость выплывает снизу (0.4 с), пропуск появляется (0.2 с) |
| 0.6 с | Фаза решения — без жёсткого лимита; тап по пропуску = зум (×1.6) |
| решение | Тап кнопки → штамп бьёт по документу (0.3 с) + звук + вспышка |
| +0.3 с | Верно: гость уходит вправо (0.5 с), жетоны летят в счётчик. Неверно: красный штамп, карточка объяснения (см. ниже) |
| +0.8 с | Следующая заявка |

**Мягкий лимит времени — терпение:** 40 с (knob 30–60). По истечении гость уходит сам: заработок 0, **ошибка не начисляется**. У последней заявки смены терпение бесконечно.

**Верно:** зелёная вспышка + звук штампа + жетоны. **Неверно:** обязательная карточка объяснения — заголовок «ОШИБКА», строка с пиктограммой несовпавшего признака: «Гость: синяя голова. Правило: не пускать синие головы», кнопка «Понятно». Без объяснения игра не продолжается.

**Точные числа режима:**

| Параметр | Значение |
|---|---|
| Слотов правил на доске | 3 (максимум активных правил) |
| Активных правил по сменам | смена 1: 1; смены 2–3: 2; смена 4+: 3 |
| Заявок в смене | смена 1: 8; смены 2–5: 10; смена 6+: 12 |
| Лимит ошибок | 3 → смена прервана (заработанное остаётся, бонус безошибочности не начислялся) |
| Время на заявку | жёсткого нет; терпение 40 с |
| Скоростной бонус | решение ≤ 10 с → +1 жетон |

## 3. Процедурная генерация

### 3.1 Признаковая модель персонажа

Персонаж = словарь атрибутов. Признак = `{id, value}`. Всё рисуется Graphics-примитивами (нулевые растровые ассеты).

| id атрибута | значения (v1) | число |
|---|---|---|
| `headForm` | круг, квадрат, треугольник, шестиугольник | 4 |
| `headColor` | красный, оранжевый, жёлтый, зелёный, синий, фиолетовый | 6 |
| `bodyForm` | прямоугольник, трапеция, овал | 3 |
| `bodyColor` | та же палитра из 6 | 6 |
| `eyes` | точки, полоски | 2 |
| `accessory` | нет, шляпа, антенна | 3 |
| `expiry` | день N (число) | — |
| `signature` | есть, нет | 2 |

**Ограничение палитры:** соседние hues запрещены, минимальная дистанция по цветовому кругу ≥ 60° (анти-баг «оранжевый vs красный на дешёвом экране»). Имя генерируется слогами («КО-РА-МУ») и **не является признаком** — никогда не проверяется.

**Пропуск** = визуализация атрибутов гостя, где каждое поле либо истинно, либо (у подделки) ровно одно ложное. `today` = календарный день от первого запуска игры (хранится в сейве). Валидный `expiry` ∈ [today, today+30]; просрочка (мутация) ∈ [today−10, today−1].

### 3.2 Типы заявок и их генерация

1. **Валидный** (ответ всегда ПРОПУСТИТЬ): атрибуты случайные с ограничением «не нарушает ни одно активное правило» (rejection sampling, максимум 20 попыток → fallback: принудительно безопасные значения); документ = точная копия.
2. **Подделка** (ответ РАЗВЕРНУТЬ): сначала генерируется валидный гость, затем мутируется **ровно одно поле** документа на значение, отличное от истинного; сам гость валиден по правилам.
3. **Нарушитель** (ответ РАЗВЕРНУТЬ): документ полностью совпадает с гостем; гость нарушает **ровно одно** активное правило.

**Доля самозванцев:** p = 0.2 в онбординг-смене 1; далее p = min(0.45, 0.25 + 0.03 × (смена − 2)). Подделка/нарушитель: 100% подделок до смены 4 (первое документное правило), затем 50/50.

> **Поправка дня 3 (2026-11-11):** «100% подделок до смены 4» оставило бы правила-запреты признаков (№1–3) мёртвыми — никто их никогда не нарушал бы. Решение: нарушители активных правил появляются со смены 2 (со вводом правила №2), минимум по одному нарушителю на каждое активное правило за смену; подделки при этом никогда не мутируют поля, закрытые активными правилами (инвариант 3.4.1 соблюдён). Документные правила (срок, подпись) вводят нарушителей-документов со своей смены. Полная директивная выборка «≥2 нарушителей + ≥2 носителей на правило» — день 4.

**Директивная выборка поверх RNG (очередь смены строится целиком до начала):**
- каждый активный тип правила представлен ≥ 2 нарушителями и ≥ 2 валидными носителями признака за смену (правило не должно быть «мёртвым»);
- не более 3 невалидных и не более 4 валидных подряд (анти-монотонность);
- первая заявка после ввода нового правила — обучающий слот: гарантированный нарушитель именно этого правила, ошибка в нём не засчитывается (см. раздел 8).

### 3.3 Сид-структура

- **Случайная смена:** seed = 32-бит (`(Date.now() ^ счётчик_запуска) >>> 0`), сохраняется в сейве для дебага.
- **Дневная смена:** seed = `(YYYY × 10000 + MM × 100 + DD) × 2654435761 mod 2³²` — вычисляется локально, одинаков у всех игроков, сервер не нужен. Дата — локальная для пользователя.
- **RNG:** mulberry32; **разные суб-потоки** для состава очереди, персонажей и документов: `rng = mulberry32(hash(seed, "queue" | "char" | "doc"))` — чтобы правки генерации персонажа не ломали состав смены.

### 3.4 Баги генерации, которых не должно быть (инварианты, покрыть unit-тестом на 1000 сидов)

1. **Двусмысленность ответа:** у каждой заявки ровно одна причина отказа и ровно один верный ответ. Подделка никогда не мутирует поле, проверяемое активным правилом; нарушитель никогда не имеет расхождений с документом. Смешанного дефекта не бывает.
2. **Конфликт активных правил:** два активных правила не могут проверять пересекающиеся множества атрибутов. Правило автоматическое: пара (A, B) запрещена, если `attrs(A) ∩ attrs(B) ≠ ∅` (пример: «не пускать синие головы» и «шляпы запрещены, кроме красных голов» оба задевают `headColor`). Проверяется при сборке активного набора.
3. **Неразличимость значений:** мутация всегда меняет значение на заведомо отличимое (другая форма / цвет с дистанцией ≥ 60°).
4. **Мёртвое правило:** снято директивной выборкой (3.2).
5. **Поля документа вне модели:** каждое поле пропуска читается либо с тела гостя, либо является документным атрибутом (`expiry`, `signature`). Ничего «просто украшающего», что можно перепутать с проверяемым.
6. **Обидный финал:** у последней заявки терпение = ∞.
7. **Обрывание прерыванием:** прерывание смены по ошибкам не может случиться на обучающем слоте (там ошибка не считается).

## 5. Экономика смены

Валюта — **жетоны**. Заработок начисляется на экране итогов.

| Параметр | Значение | Обоснование |
|---|---|---|
| Зарплата за верное решение | 11 жетонов | flat, без множителей сложности в v1 |
| Скоростной бонус (≤ 10 с) | +1 жетон | дифференцирует скор дневного лидерборда |
| Бонус за безошибочную смену | +50 | ошибка мгновенно теряет этот бонус — цена ошибки без унижения |
| Штраф за ошибку | денежного нет; 3 ошибки = прерывание | анти-фрустрация: не сжигаем заработанное |
| Прерывание смены | выплата за верные решения сохраняется, бонус 50 не начислялся | |

**Доход:** хорошая смена 12 заявок ≈ 11×12 + 12 + 50 = **194 жетона**; 2–3 смены в день ≈ 350–550.

**Инструменты v1 (ровно два), покупаются один раз, навсегда:**

| Инструмент | Цена | Эффект | Заряды |
|---|---|---|---|
| **Лупа** | 300 | тап по признаку подсвечивает его одновременно на госте и в документе (сравнение одним взглядом) | пассивна, без зарядов |
| **Детектор** | 500 | подсвечивает один несовпавший признак текущей заявки; если расхождений нет — пишет «Документ верен» (игрок понимает: искать надо нарушение правила дня) | 1 бесплатно за смену; доп. заряды — rewarded, ≤ 2 за смену |

**Темп покупок:** смена 1 ≈ 11×8+50 = 138; к началу смены 3 игрок набирает ≥ 300 → **первая покупка в первые 10–15 минут** (важно для раннего закрепления экономики). Детектор — день 2.

**Между сменами — экран «Кабинет»: жетоны, XP-бар, кнопки покупки, прервать смену.** Никаких энергий и ожиданий — смены безлимитны.

**Крутилки (curve/gate knobs, все в data-файлах):** зарплата 11 (8–15), бонус 50 (30–100), цена Лупы 300, Детектора 500, терпение 40 с, p(самозванец) 0.2→0.45.

## 6. Мета-прогрессия

**XP:** 5 за верное решение + 50 за безошибочную смену. Смена 12 заявок ≈ 110 XP.

| XP | Звание | Что открывает |
|---|---|---|
| 0 | Стажёр | — |
| 300 | Дежурный | дневная смена, ночная смена (rewarded-режим) |
| 900 | Старший дежурный | титул в меню (v2: тема стойки) |
| 2000 | Инспектор | титул |
| 4000 | Главный инспектор | титул |

Расчёт темпа: Дежурный ≈ смена 4, Старший ≈ смена 9, Инспектор ≈ смена 18. Гейт правил — только номер смены (двойной гейт не делаем).

**Ежедневная смена:** доступна раз в календарный день со звания «Дежурный»; seed = hash(дата), 12 заявок, фикс-набор правил тем же алгоритмом ротации; в v1 без призов, чисто рейтинг. Флаг «сыграна за дату D» хранится в сейве.

**Лидерборды (ровно две, Yandex SDK):**

1. **«Лучший стрик»** — рекордная серия верных решений подряд за всё время. Скор = длина стрика.
2. **«Дневная смена»** — скор дневной смены: `10 × верные + 1 × быстрые(≤10 с) + 50 × (0 ошибок)`, максимум 182. Скор сабмитится только если смена завершена (не прервана).

**Облачный сейв (после каждой закрытой заявки):** жетоны, XP, звание, номер смены, календарный день старта, стрик, рекорды, купленные инструменты, прогресс текущей смены (seed, номер заявки, ошибки), флаги дневной/ночной смены по датам. ~1–2 КБ, лимитов хватает.

## 7. Монетизация

### Rewarded (4 точки, точные награды)

| Точка | Момент | Награда | Лимит |
|---|---|---|---|
| **Прощение ошибки** | 3-я ошибка перед прерыванием | ошибка аннулируется (счётчик 3→2), смена и бонус под угрозой сохранены | 1 за смену |
| **Заряд детектора** | экран заявки, после разблокировки инструмента | +1 заряд | 2 за смену |
| **×2 жетоны** | экран итогов | удвоение начисления смены | всегда |
| **Ночная смена** | кабинет, со звания «Дежурный» | бонусный режим: 12 заявок, зарплата ×1.5 (округление вверх), ошибки не прерывают смену (бонус 50 всё равно сгорает) | 1 в день |

Все награды — комфорт или повтор, ничего необратимого в мету (столп «не плати за прогресс»).

### Interstitial-политика

- Показ **только** на экране итогов после его закрытия (переход к кабинету).
- Не чаще 1 на 3 смены и не раньше 120 с после любого показа рекламы (rewarded включительно).
- Никогда: в сменах 1–3 (онбординг), на карточке ошибки, до первого вызова `LoadingAPI.ready()`.

### Что НЕ монетизируем (жёстко)

- Не продаём ответы: детектор ограничен лимитом, «авто-решатель» не существует.
- Не продаём отключение лимита ошибок на постоянку.
- IAP отсутствуют в v1 целиком (платёжный контур — v2, только косметика).
- Прогресс никогда не блокируется без просмотра рекламы: rewarded недоступен → кнопка просто не даёт бонус, смена прерывается штатно.

## 8. UX и онбординг

**Первые 60 секунд:**

| t | событие |
|---|---|
| 0–5 с | Загрузка → заставка «СМЕНА 1» со штампом. Единственная кнопка «Начать смену», меню-лабиринта нет |
| 5–20 с | Заявка 1: **гарантированно валидный гость с зелёной головой** (не задевает правило №1). Доска: одно правило с пиктограммой «перечёркнутый синий круг» + «Не пускать синие головы». Любое решение принимается; если развернул — мягкая карточка «Гость чист: документы совпадают, правило не нарушено», ошибка НЕ считается |
| 20–35 с | Заявка 2: **гарантированный явный самозванец** — подделка по цвету головы (самый читаемый признак). Неверное решение → карточка объяснения с подсветкой несовпавшего поля. Ошибка НЕ считается (онбординг) |
| 35–60 с | Заявки 3–8: обычный поток, p = 0.2, одно правило, лимит ошибок ещё выключен. Итог: начисление, «Лупа — 300» видна в кабинете как почти достижимая |

**Обучение новому правилу (вся прогрессия, навсегда):** первая заявка после ввода правила — обучающий слот: гарантированный нарушитель этого правила; если игрок ошибся — объяснение, ошибка не засчитывается. Механики в изоляции, затем сочетание (scaffolded challenge).

**Минимум текста:** формулировки ≤ 8 слов, всё дублируется пиктограммами; русский язык обязателен по требованиям платформы, но чтение не является барьером — правило читается по иконке за 2 с.

**Фидбек ошибок** — карточка объяснения обязательна, всегда с пиктограммой конкретного признака. Никогда «Неверно» без причины.

**Touch/mouse паритет:** вся игра — тап/клик, **никакого drag и hover-only**. Зум документа — тап (не наведение). Кнопки ≥ 72×72 px, отступы ≥ 16 px. Pointer Events Phaser покрывают обе схемы без ветвлений.

**Вес билда:** цель < 5 МБ: нулевые растровые ассеты (всё Graphics), 1 шрифт (system или subset webfont), SFX ≤ 100 КБ суммарно.

## 9. Edge cases и анти-фрустрация

| Ситуация | Поведение |
|---|---|
| Игрок тыкает наугад | Математически убыточно: 3 ошибки = прерывание без бонуса; стрик и дневной скор падают. Карточка объяснения после каждого промаха делает обучение быстрее угадывания |
| AFK / свернул вкладку | Терпение 40 с → гость уходит (не ошибка). `visibilitychange` → автопауза: таймеры терпения останавливаются. После 3 уходов подряд — экран «Смена приостановлена», кнопка «Продолжить» |
| Два правила «противоречат» на одной заявке | Невозможно по построению: правила активируются только на непересекающихся атрибутах (3.4.2), нарушитель нарушает ровно одно. Unit-тест инварианта |
| Рестарт смены | «Прервать смену» в кабинете: выплата за верные, бонус теряется; следующая смена — **новый сид** (заучивание очереди исключено) |
| Закрыл вкладку посреди смены | Прогресс пишется после каждой заявки (seed, номер, ошибки); возврат → продолжение с той же заявки той же очереди |
| Rewarded недоступен / отклонён | Штатная деградация: бонус не выдаётся, прерывание происходит. Прогресс никогда не блокируется |
| Смена даты во время игры | Уже сыгранная дневная смена остаётся засчитанной за свою дату (флаг в сейве); новый день → новый сид |
| Последняя заявка | Терпение ∞; прерывание по ошибкам на последней заявке = смена всё равно закрыта, бонус по общему правилу |
| «Слишком много самозванцев подряд» | Капы директивной выборки: ≤ 3 невалидных и ≤ 4 валидных подряд |
| Залипание на заявке (не понимает) | Детектор (после покупки) + обучающие слоты; в v1 больше ничего — таймера давления нет |

**Kill-гейт недели 1 (критерии продолжения):**
1. 5/5 тестировщиков после 10 секунд наблюдения за чужой партией правильно отвечают на вопрос «что нужно делать?» (опрос вслух, чек-лист из 5 вопросов: цель, два действия, источник правил, что такое самозванец).
2. Средняя сессия ≥ 3 мин (секундомер: от первого тапа «Начать смену» до закрытия вкладки; ≥ 2 смен у majority).
3. Ни один тестировщик не называет игру «непонятной» в свободном комментарии.

**Замер:** ручной чек-лист (да/нет по каждому из 5 пунктов на человека), секундомер, счётчик ошибок онбординга (цель ≤ 1 у 4 из 5). Провал любого критерия = итерация кора на неделе 2, мета не трогается.
